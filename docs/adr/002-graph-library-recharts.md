# ADR-002: グラフライブラリに Recharts を採用

## ステータス
承認（Accepted）

## 日付
2026-05-09

## 背景

hizamaru では以下のグラフを表示する必要がある：
- ダッシュボード：資産推移グラフ（折れ線グラフ）
- タイムライン：年別の必要資金表示
- 家計簿：月別支出グラフ（棒グラフ）
- シナリオ比較：複数シナリオの資産推移比較グラフ

React/Next.js との統合が容易で、学習曲線が緩く、必要なグラフ型をすべてカバーするグラフライブラリが必要。

## 候補と評価

| ライブラリ | 学習曲線 | React 統合 | ファイルサイズ | hizamaru 適性 |
|---------|--------|----------|----------|-----------|
| **Recharts** | ★★☆ やさしい | ネイティブ | 中程度 | ⭐⭐⭐ |
| Chart.js | ★★★ 難しい | ラッパー必要 | 小さい | ⭐⭐☆ |
| Victory | ★★★ 難しい | ネイティブ | 中程度 | ⭐⭐☆ |
| Plotly.js | ★★★★ 難しい | ラッパー必要 | 大きい | ⭐☆☆ |
| Nivo | ★★★★ 難しい | ネイティブ | 大きい | ⭐☆☆ |

## 決定

**Recharts を採用する。**

## 理由

### 1. React コンポーネント型
- グラフを React コンポーネントとして記述（JSX）
- 他の React コンポーネントとの組み合わせが自然
- State や Props との連携が直感的

**コード例:**
```jsx
import { LineChart, Line, XAxis, YAxis } from 'recharts';

export function AssetChart({ data }) {
  return (
    <LineChart width={600} height={300} data={data}>
      <XAxis dataKey="year" />
      <YAxis />
      <Line type="monotone" dataKey="balance" stroke="#8884d8" />
    </LineChart>
  );
}
```

### 2. hizamaru で必要なグラフがすべてカバー
- 折れ線グラフ（資産推移）
- 棒グラフ（月別支出）
- 複数系列のグラフ（シナリオ比較）
- すべてが簡潔な API で実装可能

### 3. 学習曲線が緩い
- ドキュメントが充実している
- コミュニティが活発
- 初心者でも簡単に始められる

### 4. 開発速度
- セットアップが最小限（`pnpm add recharts`）
- グラフの追加・修正が迅速
- プロトタイピングから本実装までスムーズ

### 5. shadcn/ui との相性
- shadcn/ui コンポーネントと共存可能
- デザイン統一が容易（Tailwind CSS と同じ色パレット使用可能）

## 影響

### ポジティブ
- 開発速度の向上
- グラフ実装の一貫性
- メンテナンスの容易さ

### ネガティブ
- 3D グラフには非対応（ただし hizamaru では不要）
- 高度なカスタマイズには制限がある可能性

## 代替案と選定されない理由

### Chart.js
- **理由:** キャンバスベースで、React との連携が不自然。ラッパーライブラリが必要。
- **採用条件:** バンドルサイズを極小にしたい場合（現在は不要）

### Victory
- **理由:** 学習曲線が Recharts より高く、コミュニティが小さい。
- **採用条件:** 複雑なアニメーション・カスタマイズが必須の場合（現在は不要）

### Plotly.js / Nivo
- **理由:** オーバースペック。ファイルサイズが大きく、学習コストが高い。
- **採用条件:** 3D グラフや複雑な可視化が必須の場合（現在は不要）

## 次のステップ

1. `pnpm add recharts` でインストール
2. ダッシュボード用の資産推移グラフ実装
3. グラフ用の共通コンポーネント定義（色パレット、フォーマット など）
4. 各画面でのグラフ埋め込み

## 将来の変更検討

- **バンドルサイズ最適化が必須な場合**: Chart.js への乗り換え検討
- **複雑な可視化要件が出た場合**: Nivo への乗り換え検討
